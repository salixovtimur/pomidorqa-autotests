# PomidorQA — автотесты

Автотесты учебного приложения [PomidorQA](https://aiqa.su/pomidorqa) — сервиса, где участники выкладывают свободные слоты и бронируют встречи друг с другом.

Стек: **Playwright + TypeScript**. Три уровня пирамиды: unit, API и E2E.

![CI](https://github.com/salixovtimur/pomidorqa-autotests/actions/workflows/ci.yml/badge.svg)

---

## Как запустить

Нужен Node.js 24.

```bash
npm ci                              # зависимости строго из lock-файла
npx playwright install chromium     # браузер для E2E
```

```bash
npm run lint         # ESLint
npm run typecheck    # проверка типов
npm run test:unit    # unit — чистые функции, без браузера
npm run test:api     # API — против локального мок-сервера
npm run test:e2e     # E2E — против живого стенда aiqa.su
npm test             # всё сразу
npm run report       # открыть HTML-отчёт последнего прогона
```

Стенд можно подменить: `POMIDORQA_BASE_URL=http://localhost:3000 npm run test:e2e`.

## Что покрыто

**Unit** — пересечение слотов, отображение времени в часовом поясе участника, валидация пароля.

**API** — бронирование слота, повторная бронь занятого, бронь собственного слота, бронь в прошлом, несуществующий слот, гонка двух одновременных броней, регистрация и дубль почты.

**E2E, 19 тестов в пяти файлах:**

| Файл | Что проверяет |
|---|---|
| `auth-flow.spec.ts` | форма регистрации пускает внутрь, занятая почта отклоняется, неверный пароль и несуществующая почта дают одинаковую ошибку |
| `booking-flow.spec.ts` | гонка за слот: первый гость бронирует, второй получает ошибку, встреча видна обеим сторонам |
| `booking-cancel.spec.ts` | гость отменяет встречу, отмену видят обе стороны и она переживает перезагрузку |
| `catalog-search.spec.ts` | счётчик свободных слотов в карточке, в карточке видны только навыки «могу помочь» |
| `profile-flow.spec.ts` | поля профиля сохраняются на сервер, навыки расходятся по блокам, пустой навык не добавляется |

## Как это устроено

```
tests/e2e/      сценарии: кто что делает и что должно получиться
tests/api/      HTTP-проверки против локального мок-сервера
tests/unit/     чистые функции
tests/pages/    Page Object: локаторы и действия на экране
tests/helpers/  тестовые данные, создание и уборка участников
src/pyramid/    код, который проверяют unit- и API-тесты
```

**Подготовка через API, проверка через UI.** Участник нужен почти каждому сценарию, но саму форму регистрации проверяет только `auth-flow.spec.ts`. Везде остальное аккаунт заводится запросом `POST /api/pomidorqa/test/accounts` — это быстрее и убирает лишний повод для флака. Ответ приносит куку сессии, и поскольку `context.request` делит хранилище кук со страницами контекста, браузер оказывается авторизован без отдельного входа.

**Уборка обязательна.** Стенд общий и живой, мусор на нём видят все. Каждый тест удаляет созданные аккаунты в `afterEach`; удаление каскадное — вместе с участником уезжают его навыки, слоты и брони. `DELETE` не принимает идентификатор, он сносит владельца пришедшей куки, поэтому действует правило «один браузерный контекст — один участник». Контекст попадает в список на уборку **до** первого действия, которое может упасть, иначе упавшая подготовка оставит участника на стенде навсегда.

**Два пайплайна вместо одного.** [`ci.yml`](.github/workflows/ci.yml) на каждый push гоняет линт, типы, unit и API — они герметичные и не зависят ни от чего внешнего. [`e2e.yml`](.github/workflows/e2e.yml) ходит на живой общий стенд, поэтому запускается по расписанию и по кнопке, с параметром «сколько раз повторить» для проверки на флак. Так падение чужого сервера не красит основную ветку, а сигнал о собственном коде остаётся честным.

**Гонка гидратации.** Переход в карточку участника из каталога — клиентская навигация Next.js: разметка календаря уже на месте, а обработчики React ещё не навешаны, и клик уходит впустую. Замеряно: без повтора окно брони открывается в 3 попытках из 8, с повтором — в 8 из 8. Поэтому в `BookingPage.openFirstSlot` стоит цикл с дедлайном.
