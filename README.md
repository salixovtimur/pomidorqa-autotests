# Автотесты PomidorQA

[![CI](https://github.com/salixovtimur/pomidorqa-autotests/actions/workflows/ci.yml/badge.svg)](https://github.com/salixovtimur/pomidorqa-autotests/actions/workflows/ci.yml)

Набор автотестов на [PomidorQA](https://aiqa.su/pomidorqa) — сервис 25-минутных звонков для
QA-специалистов: регистрация, профиль с навыками, слоты доступности, каталог участников,
бронирование и отмена встречи.

Продукт тестируется как чёрный ящик: исходников приложения у набора нет, доступен только живой
стенд. Поэтому покрытие считается от функциональных требований, а не от строк кода.

## Покрытие требований

**42 из 50 требований закрыты автотестами — 84%.** Статус определён у всех 50.

| Статус | Требований | Доля |
|---|---|---|
| `automated` — тест упадёт, если поведение сломается | 42 | 84% |
| `partial` — покрыта наблюдаемая часть правила, серверная недостижима | 5 | 10% |
| `known defect` — продукт расходится с требованием | 1 | 2% |
| `out of scope` — состояние недостижимо через интерфейс | 2 | 4% |

[Матрица покрытия](docs/coverage-matrix.md) — таблица «требование → статус → тест» по каждому
из 50 пунктов [спецификации](requirements.md).

## Что проверяет проект

Главный риск продукта — встреча, о которой договорились два человека. Она не должна теряться,
дублироваться и доставаться двоим сразу. Вокруг этого построен набор:

- сквозной путь «зарегистрировался → заполнил профиль → открыл слот → нашёлся в каталоге →
  его забронировали → встреча видна обоим»;
- гонка за один слот: подтверждённой остаётся ровно одна бронь, второй получает ошибку;
- отмена с обеих сторон, освобождение слота и повторное бронирование другим участником;
- запрет поздней отмены: меньше двух часов до начала — сервис отказывает;
- границы роли: гость смотрит каталог и профили, но бронировать не может;
- часовой пояс: время слота показывается в поясе владельца, а не смотрящего.

## Цифры прогона

| Уровень | Тестов | Время | В среднем на тест |
|---|---|---|---|
| unit | 10 | 0,04 с | 4 мс |
| api | 8 | 0,3 с | 40 мс |
| e2e | 39 | 178 с | 4,6 с |

Полный набор — **57 тестов**. Локально на пяти воркерах прогон занимает **42 секунды**, в CI идёт
в один поток, чтобы не нагружать общий стенд, и укладывается в три минуты. Один тест
падает намеренно: `known-defects` помечен `test.fail()`, пока дефект жив.

```bash
npm run gate      # типы → линт → формат → все три уровня → метрики
npm run metrics   # сводка по последнему прогону: уровни, время, повторы, самые долгие
```

## Находки

**KD-1 — каталог ищет по навыкам обоих типов.** По требованию поиск ограничен разделом «могу
помочь», фактически находит и тех, кто тему только хочет разобрать. Бронь уходит не тому, встреча
проходит впустую. Тест написан по требованию и помечен `test.fail()`: пока дефект жив, прогон
зелёный, когда починят — Playwright скажет «expected to fail, but passed». Так дыра не
превращается в зелёную галочку.

**Гонка гидратации Next.js.** Переход в карточку участника из каталога — клиентская навигация:
разметка календаря уже на месте, обработчики React ещё не навешаны, клик уходит впустую. Замерено:
без повтора окно брони открывается в 3 попытках из 8, с повтором — в 8 из 8. Поэтому в
`BookingPage.openFirstSlot` стоит цикл с дедлайном.

**Часовой пояс браузера фиксируется в конфиге.** Без `timezoneId` проверка «гость видит время в
поясе хоста» держалась бы на том, что у машины прогона пояс случайно не совпал с поясом хоста.
Теперь браузер всегда в `Europe/Moscow`, хост в сценарии переключается на `Asia/Vladivostok` —
расхождение заданное, а не случайное.

**Форма профиля стирает соседнюю форму.** Сохранение личных данных перерисовывает страницу и
обнуляет поле навыка, если его заполнить сразу следом. Сценарии между двумя формами перезагружают
страницу.

## Архитектура

```
tests/unit/      чистые функции — без сети и браузера
tests/api/       правила бронирования по HTTP — без интерфейса
tests/e2e/       пользовательские сценарии в браузере
tests/pages/     Page Object: локаторы и действия одного экрана
tests/helpers/   тестовые данные, подготовка через API, гарантированная уборка
scripts/         сводка метрик по отчёту прогона
docs/            матрица покрытия требований
```

Разделение жёсткое: в спеке — сценарий и проверки, в Page Object — экран, в хелпере — участник.
Локаторов в спеках нет, `expect` в Page Object нет.

**Подготовка через API, проверка через интерфейс.** Участник нужен почти каждому сценарию, но саму
форму регистрации проверяет только `auth-flow`. Везде остальное аккаунт заводится запросом
`POST /api/pomidorqa/test/accounts`: быстрее и на один повод для флака меньше. Ответ приносит куку
сессии, а `context.request` делит хранилище кук со страницами контекста — браузер оказывается
авторизован без отдельного входа.

**Уборка обязательна.** Стенд общий и живой, мусор на нём видят все. Каждый тест удаляет созданные
аккаунты в `afterEach`, удаление каскадное — вместе с участником уезжают навыки, слоты и брони.
`DELETE` не принимает идентификатор, он сносит владельца пришедшей куки, отсюда правило «один
браузерный контекст — один участник». Контекст попадает в список на уборку до первого действия,
которое может упасть: иначе упавшая подготовка оставит участника на стенде навсегда.

**Три пайплайна.** [`ci.yml`](.github/workflows/ci.yml) на каждый push гоняет типы, линт, формат,
unit и API — они герметичные, а метрики прогона уходят в сводку запуска.
[`e2e.yml`](.github/workflows/e2e.yml) ходит на общий живой стенд, поэтому работает по расписанию
и по кнопке, с параметром «сколько раз повторить» для проверки на флак: падение чужого сервера
не красит основную ветку. [`claude-review.yml`](.github/workflows/claude-review.yml) вешает
AI-ревью на каждый pull request, сверяясь со сводом правил из [`CLAUDE.md`](CLAUDE.md).

## Как запустить

Нужен Node.js 24.

```bash
npm ci
npx playwright install chromium

npm test              # все три уровня
npm run test:e2e      # только браузерные сценарии
npm run report        # HTML-отчёт с трейсами упавших шагов
```

Стенд по умолчанию — продакшен, переопределяется переменной:
`POMIDORQA_BASE_URL=http://localhost:3000 npm run test:e2e`
